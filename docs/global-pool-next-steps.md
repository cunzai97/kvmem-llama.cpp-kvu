# Remaining work before the agreed design is complete

The feature branch supports a soft global trunk-KV RAM budget, complete-block sharing and COW on exact-checkpoint edit forks (including an MTP follower mirror). Real V100 MTP A→B→A fork at row 645 was verified. It is deployed in the local V100 trial profile for user testing; this is not broad hardware validation or a production-readiness claim. The following work remains:

1. **Current requested recovery scope: missing suffix only.** The feature branch recovers a contiguous missing suffix from an exact saved recurrent/MTP checkpoint while retaining physical prefix blocks; real V100 MTP A→B→A under a 16 MiB soft cap hit 640 prefix tokens after eviction and replayed only the missing suffix plus new prompt. Internal holes and missing checkpoints deliberately take an explicit full miss. The user does not currently require middle-hole KV reuse; if that becomes a requirement, it needs a separate checkpoint-aware range replay design that preserves valid suffix cells. Media-path suffix recovery still needs dedicated validation.
2. **General edit positions.** Current forks require a saved exact recurrent checkpoint ≥128 rows, a complete packed-KV mirror, and no session files. The server retains only four checkpoints. Implement a safe short-gap replay from the nearest preceding checkpoint, or a bounded anchor policy, to support arbitrary edit locations. Old RoPE'd packed K is reusable only at its original position. Preserve distinct GPU slots/runtimes for both branches; provide explicit behavior when conversation count/byte quotas require eviction.
3. **Physical accounting and performance.** Replace O(all stores × blocks × layers) reconciliation with incremental unique-payload accounting and a cold-block index; touch blocks on actual retrieval, not merely writes. Include MTP mirrors, checkpoint/tail vectors, metadata and staging in process-level memory planning (or report separate bounded budgets). The current trunk limit is a soft cap, not an RSS guarantee. Avoid unconditional full drain/restage at each conversation switch.
4. **Failure safety and validation.** Harden COW/allocation and multi-layer write exceptions so failed writes cannot leave a selectable partly valid store; add allocation/stage-in fault injection and concurrent truncate/evict stress. Test fork with insufficient child slots and low RAM budget, image branches with media-prefix matching, long-context latency/RSS, and exact missing-page replay metrics. Keep this deployment isolated from upstream master, preserve the previous launcher for rollback, and expand validation before treating it as production-ready.
